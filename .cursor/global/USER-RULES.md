# Cursor User Rules — глобальный always-on слой (паритет с Claude)

> Вставь этот текст в **Cursor Settings → Rules → User Rules**. Это компактный глобальный слой,
> действующий во всех папках. Полный набор из 18 правил живёт в `.cursor/rules/*.mdc` каждого
> вендоренного проекта (источник истины — ваша копия репозитория agents-core).

---

## Operating model (orient → structure → act → review → close)

В начале сессии — сориентироваться до действий. Если есть `roadmap/_status.md` — прочитать и восстановить
контекст (тип сессии: новая задача / продолжение / баг / review / refinement / release). Определить цель
сессии и что считается done. Нетривиальную задачу структурировать до исполнения, большие — декомпозировать.

## Shell discipline

Перед shell-действием: нужен ли shell вообще; цель и ожидаемый результат; read-only или мутирующее.
Особая осторожность и явное обоснование: delete, overwrite, mass edits, git-мутации, миграции, смена прав,
установка зависимостей. После команды — интерпретировать вывод до продолжения.

## Edit discipline

После правки: что и какого типа изменилось; двигает ли это цель, не уполз ли scope, не выросла ли сложность
зря. Проверить соседние файлы / типы / тесты / импорты / конфиг — не оставить half-fixed состояния.

## Review before done

Реализацию не выдавать за завершённую без review. Отделять «готово» (заявление) от проверенного факта.
Каждое изменение должно делать систему лучше, а не просто другой.

## Closure discipline

Сессия сходится к: завершённый кусок / задокументированный блокер / явный следующий шаг / release summary.
Обновлять `roadmap/_status.md`, если он есть. Не останавливаться в размытом состоянии.

## Quality / security / tools

- Продукт-интент и инженерное качество первичны; UI/UX по базовым стандартам; admin- и user-flow разделять.
- Секреты не коммитить, не логировать, не выводить.
- MCP/инструменты (context7, playwright, figma) — по своим `*-discipline` правилам: сначала локальный контекст
  и мысль, потом внешняя справка; инструмент — не замена рассуждению.

---

**Внутри вендоренного проекта** действует полный слой из `.cursor/rules/` — он строже и авторитетнее этого
краткого глобального. Здесь — базовая дисциплина для работы вне проектов, чтобы Cursor был always-on, как Claude.
