# Глобальное окружение Claude Code — слой agents-core (always-on во всех папках)

Этот файл — user-level memory (`~/.claude/CLAUDE.md`): грузится в **каждой** сессии Claude Code
независимо от текущей папки. Он активирует общий слой agents-core глобально.

**Источник истины:** ваша копия репозитория agents-core, локально — `__AGENTS_CORE_SRC__`.
Файл сгенерирован установщиком `scripts/install-global.sh` из `.claude/global/CLAUDE.md`.
Правки вносить **в репо** (не в установленную копию) и переустанавливать.

---

## Импорт канонического слоя (протоколы сессии + 18 правил)

@__AGENTS_CORE_SRC__/CLAUDE.md

---

## Точки входа (работают из любой папки)

- **«создай проект <имя> [repo]»** / «new project <name>» →
  `bash __AGENTS_CORE_SRC__/scripts/create-project.sh <имя> [repo]`
  (создаёт папку `$PROJECTS_DIR/<имя>`, приватный репо `<ваш-github-логин>/<имя>`,
  вживляет слой, коммит, push, регистрирует в реестре пропагации).
- **обновить слой в текущем проекте** → `bash .cursor/sync.sh`
  (или `AGENTS_CORE_SRC=__AGENTS_CORE_SRC__ bash .cursor/sync.sh`).
- **проверить синхронность окружений Claude ↔ Cursor** →
  `bash __AGENTS_CORE_SRC__/scripts/check-parity.sh`.

---

## Приоритет и облако

Внутри вендоренного проекта его собственные `CLAUDE.md` и `.claude/` (лежащие в репо проекта)
авторитетны и дублируют этот слой — это ожидаемо и безопасно (контент идентичен).
В облаке (Claude web) действует **только вендоренный слой проекта** — этот глобальный файл туда не попадает,
поэтому за облачный паритет отвечает пер-проектный вендоринг.
