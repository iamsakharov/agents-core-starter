# Глобальное окружение Claude Code — слой agents-core (always-on во всех папках)

Этот файл — шаблон user-level memory (`~/.claude/CLAUDE.md`): она грузится в **каждой** сессии
Claude Code независимо от текущей папки и активирует слой agents-core глобально.

**Источник истины:** твой чекаут репо agents-core — `__AGENTS_CORE_SRC__`.
Установленная копия генерируется скриптом `scripts/install-global.sh` из этого шаблона.
Правки вносить **в репо** (не в установленную копию) и переустанавливать.

---

## Импорт канонического слоя (протоколы сессии + 18 правил)

@__AGENTS_CORE_SRC__/CLAUDE.md

---

## Точки входа (работают из любой папки)

- **«создай проект <имя> [repo]»** / «new project <name>» →
  `bash __AGENTS_CORE_SRC__/scripts/create-project.sh <имя> [repo]`
  (создаёт папку в `$PROJECTS_DIR`, приватный GitHub-репо, вживляет слой, коммит, push,
  регистрирует в реестре пропагации).
- **обновить слой в текущем проекте** → `bash .claude/sync.sh`
  (или `AGENTS_CORE_SRC=__AGENTS_CORE_SRC__ bash __AGENTS_CORE_SRC__/scripts/sync.sh .`).
- **проверить целостность слоя** → `bash __AGENTS_CORE_SRC__/scripts/check-layer.sh`.

---

## Приоритет и облако

Внутри вендоренного проекта его собственные `CLAUDE.md` и `.claude/` (лежащие в репо проекта)
авторитетны и дублируют этот слой — это ожидаемо и безопасно (контент идентичен).
В облаке (Claude Code web) действует **только вендоренный слой проекта** — этот глобальный файл
туда не попадает, поэтому за облачный паритет отвечает пер-проектный вендоринг.
