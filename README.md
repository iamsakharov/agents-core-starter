# agents-core — стартовый шаблон

Готовая «операционная система» для разработки с ИИ-ассистентами **Cursor** и **Claude Code**.
Задаёт единый рабочий цикл: **планирование → исполнение → review → доработка → закрытие**.

Оба ассистента начинают работать по одним и тем же правилам, ролям и навыкам — предсказуемо,
аккуратно и без хаоса «сделал что-то и бросил».

> Это **обезличенный шаблон**. Внутри нет ни секретов, ни ключей, ни личных данных — им можно
> безопасно делиться. Свои ключи и логины вы подставляете у себя локально (см. [INSTALL.md](INSTALL.md)).

---

## Что это даёт

- **Единые правила поведения** (17 штук): как планировать, не расползаться по scope, обязательно
  делать review перед «готово», беречь секреты, дисциплина git и т.д.
- **Роли-субагенты**: планировщик, ревьюер, аналитик задач, ведущий эпика и др.
- **Навыки (skills)**: пошаговое исполнение больших задач, разбор багов, архитектурный review,
  финальный summary и другие.
- **Подключение инструментов (MCP)**: свежая документация библиотек (Context7), браузер (Playwright),
  Figma — по желанию.
- **Два «дома» — Cursor и Claude** работают синхронно от одного источника истины.
- **Раздача правил по проектам**: каждый ваш проект получает слой физически (копией), поэтому правила
  работают и на компьютере, и в облаке (Cursor iOS, Claude web).

## Что внутри

```
.cursor/
  agents/     ← субагенты: планирование, review, доработка, статус
  rules/      ← 17 всегда-активных правил (+ rules/local/ под ваши правила)
  skills/     ← навыки исполнения: plan-performer, release-summary и др.
  hooks.json  ← хуки жизненного цикла
  mcp.json    ← инструменты MCP (ключи берутся из переменных окружения, не хранятся здесь)
  global/     ← глобальный слой Cursor (User Rules)
.claude/
  agents/, skills/  ← зеркало для Claude Code
  global/           ← глобальный слой Claude (~/.claude/CLAUDE.md)
  settings.json     ← базовые настройки (пустой allowlist — заполните под себя)
CLAUDE.md     ← канонический always-on слой (17 правил + протоколы сессии)
AGENTS.md     ← точка входа, которую Cursor читает автоматически
scripts/
  install-global.sh         ← активировать слой глобально в Claude Code (~/.claude)
  install-cursor-global.sh  ← активировать слой глобально в Cursor (~/.cursor)
  check-parity.sh           ← проверить, что оба «дома» синхронны
  sync.sh                   ← вживить/обновить слой в репозитории проекта
  setup-new-project.sh      ← слой + roadmap в существующей папке
  create-project.sh         ← новый проект: папка + git + слой + GitHub-репо + push
  templates/                ← базовые шаблоны (settings, mcp, environment)
projects.json          ← реестр ваших проектов для авто-раздачи обновлений (пустой)
roadmap/               ← живой статус задач (шаблон)
docs/                  ← model-tiering.md (модели субагентов), cloud-setup.md (облако)
.github/workflows/     ← propagate.yml: авто-раздача обновлений слоя в ваши проекты
```

## Быстрый старт

Полная пошаговая установка — в **[INSTALL.md](INSTALL.md)**. Если совсем коротко:

```bash
# 1. склонировать шаблон к себе
git clone https://github.com/<ваш-логин>/agents-core-starter.git ~/agents-core
cd ~/agents-core

# 2. активировать глобально (то, чем пользуетесь)
bash scripts/install-global.sh          # для Claude Code
bash scripts/install-cursor-global.sh   # для Cursor

# 3. проверить синхронность
bash scripts/check-parity.sh
```

Перезапустите Cursor / Claude Code — правила подхватятся во всех папках.

## Как это устроено (два «дома» и раздача)

- **Источник истины** — эта папка. Меняете правило здесь → переустанавливаете → меняется поведение
  обоих ассистентов.
- **Глобальная активация** (скрипты `install-*global.sh`) включает слой во всех папках на вашем
  компьютере через `~/.claude` и `~/.cursor`.
- **Вендоринг в проект** (`sync.sh` / `create-project.sh`) кладёт слой физически в репозиторий проекта —
  копией, а не ссылкой. Это нужно, чтобы облачные агенты (которые видят только клон репо) тоже
  работали по правилам.
- **Авто-раздача** (`propagate.yml`) — когда вы правите слой в своём репозитории, GitHub Action
  разносит обновление во все зарегистрированные проекты отдельными pull-request'ами. Настраивается
  по желанию (см. [docs/cloud-setup.md](docs/cloud-setup.md)).

## Безопасность

- В шаблоне **нет секретов**: ключи MCP (Context7 и пр.) подставляются из переменных окружения
  (`${CONTEXT7_API_KEY}`), а не хранятся в файлах.
- `PROPAGATE_TOKEN` для облачной раздачи — это **имя** GitHub-секрета, который вы создаёте у себя;
  значение в репозиторий не попадает.
- `.claude/settings.json` идёт с пустым allowlist — вы сами решаете, что разрешать.
