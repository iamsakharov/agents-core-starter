# Установка

Пошагово. Рассчитано на то, что вы не обязательно разработчик — все команды можно копировать как есть.
Работает на macOS и Linux (на Windows — через WSL).

---

## 0. Что понадобится

**Обязательно:**
- **Cursor** и/или **Claude Code** — то, чем вы пользуетесь.
- **git** — система контроля версий. Проверить: `git --version`. Нет — поставьте с https://git-scm.com.

**Понадобится только для отдельных функций (можно позже):**
- **GitHub CLI (`gh`)** — чтобы скрипт `create-project.sh` сам создавал репозитории.
  Установка: https://cli.github.com, затем `gh auth login`. Без этого создание проектов недоступно,
  но всё остальное работает.
- **Ключ Context7** — для подсказок по свежей документации библиотек. Без него Context7 просто не
  активен; Playwright и Figma работают без ключа.

---

## 1. Скачать шаблон к себе

Склонируйте репозиторий в удобную папку. Рекомендуем `~/agents-core`:

```bash
git clone https://github.com/<ваш-логин>/agents-core-starter.git ~/agents-core
cd ~/agents-core
```

> `<ваш-логин>` — замените на свой логин GitHub (или на логин того, кто вам дал ссылку).
> Папку можно назвать как угодно — скрипты определяют своё расположение автоматически.

---

## 2. Активировать слой глобально

Это включит правила, роли и навыки **во всех папках** на вашем компьютере.
Запустите то, чем пользуетесь (можно оба):

```bash
# для Claude Code
bash scripts/install-global.sh

# для Cursor
bash scripts/install-cursor-global.sh
```

Что делают скрипты:
- ставят глобальный слой в `~/.claude` и/или `~/.cursor`;
- перед этим делают **резервную копию** ваших текущих настроек (в `backups/`);
- прописывают MCP-серверы.

**Перезапустите Cursor / Claude Code**, чтобы изменения подхватились.

---

## 3. Проверить, что всё синхронно

```bash
bash scripts/check-parity.sh
```

Всё зелёное — оба «дома» (Cursor и Claude) настроены одинаково. Готово: откройте любую папку, и
ассистент уже работает по правилам.

---

## 4. (Опционально) Ключ Context7

Если хотите подсказки по актуальной документации библиотек — задайте ключ в переменной окружения.
Добавьте строку в `~/.zshrc` (или `~/.bashrc`):

```bash
export CONTEXT7_API_KEY="ваш-ключ"
```

Ключ получается на https://context7.com. После правки — новый терминал и перезапуск ассистента.
Ключ хранится только у вас в окружении; в репозиторий он не попадает.

---

## 5. (Опционально) Создать первый проект

Требует настроенного `gh` (см. шаг 0).

```bash
bash scripts/create-project.sh мой-проект
```

Скрипт создаст папку `~/projects/мой-проект`, положит туда слой, сделает git-репозиторий,
создаст **приватный** репозиторий на GitHub и запушит. Логин владельца берётся из `gh` автоматически.

Настроить можно переменными окружения:

```bash
PROJECTS_DIR=~/code GH_OWNER=мой-логин VISIBILITY=public \
  bash scripts/create-project.sh мой-проект
```

Или просто попросите ассистента словами: **«создай проект `мой-проект`»** — сработает правило
`project-bootstrap`.

---

## 6. (Опционально) Облачная авто-раздача обновлений

Если хотите, чтобы правки слоя автоматически разъезжались по вашим проектам через GitHub Action —
см. **[docs/cloud-setup.md](docs/cloud-setup.md)**. Там про секрет `PROPAGATE_TOKEN` и реестр
`projects.json`. Для локальной работы это не нужно.

---

## Обновление слоя позже

Правьте слой в этой папке (`~/agents-core`), затем переустановите:

```bash
cd ~/agents-core
git pull                              # если тянете обновления из своего репо
bash scripts/install-global.sh        # и/или install-cursor-global.sh
```

Обновить конкретный проект вручную:

```bash
cd путь/к/проекту
AGENTS_CORE_SRC=~/agents-core bash .cursor/sync.sh .
```

---

## Если что-то не так

- **`check-parity.sh` ругается** — перечитайте, какой из «домов» рассинхронен, и перезапустите
  соответствующий `install-*global.sh`.
- **Context7 не активен** — проверьте, что `CONTEXT7_API_KEY` задан в окружении (`echo $CONTEXT7_API_KEY`)
  и вы перезапустили ассистента.
- **`create-project.sh` не может определить владельца** — выполните `gh auth login` или задайте
  `GH_OWNER=<ваш-логин>`.
- **Хочу откатить** — установщики кладут резервные копии в `~/.claude/backups/` и `~/.cursor/backups/`.
